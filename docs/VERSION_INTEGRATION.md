## 页面看起来不一致的原因

旧 GitHub 版本注册了 `ai-learning-platform-v1` 缓存，并优先返回旧首页和脚本。本次对照发现，线上服务器首页已是 3.0 源码，但浏览器标签仍显示旧标题“AI大学习平台”；上一版静态构建未发布用于退役旧 worker 的 `service-worker.js`，该 URL 返回 404。这是已确认的升级缺口，可能导致用户继续打开旧界面。

3.1 继续在原 URL 发布退役脚本：仅删除本应用的旧缓存，注销旧 worker，刷新本应用页面，保留 URL 中的课程位置与全部 localStorage。根首页引用 `releases/<版本-内容哈希>/` 下的整套模块，静态和动态 import 均在这一目录解析，避免新入口引用旧模块。

学习数据依赖浏览器 origin。本机地址、Sites 地址和 GitHub 地址各自独立，不能隔着网址自动读取。原地址的数据不会因 GitHub 发布而删除；在原地址导出后，可在正式站点“设置 → 导入备份 → 合并”恢复。升级不清空数据，不将别人的演示记录写入个人进度。

## 统一发布与验证

正式网址为 `https://lucyio02-dev.github.io/AI-Learning/`。旧 Sites 入口保留迁移说明和原地址数据导出，继续学习转到正式网址，避免各自维护一套内容。

流程为：功能分支 → PR 校验 → 合并发布分支 → GitHub Pages 构建 `dist/`。发布包只含浏览器资源，`release.json` 记录版本、源码 SHA、构建时间和资源目录；正式迭代以 Git 标签记录。后端与完整实验脚本在同一仓库中维护。

验证包含：现有的迁移、内容、实验引擎与 API 回归，以及新增的缓存退役、模块图完整性、动态 import 保持在同一发布目录的回归。当前 GitHub 在线版仍需独立计算服务才能运行真实模型、embedding、Python 训练和账户同步；不能把浏览器演示视为这些服务已经在线。
