## 必须优先处理的缺陷

P1 表示可能泄露/丢失数据或阻断核心流程；P2 表示功能、评价或教学结果不可靠。

### 1. P1：静态服务可绕过账户认证读取后端数据

- 位置：`server/index.js:140`。
- 静态服务只限制路径在整个仓库内，没有排除 `server/data`、`.git` 等目录。
- 在未带 Authorization 的请求中，`/server/data/users/index.json` 和 `/.git/config` 均返回 200。本次只输出状态与字节数，没有输出账户索引内容。
- 影响：默认数据目录下的账户索引（含密码哈希）、用户数据文件可能被静态路径直接读取。同步 API 的 401 并不能保证数据隔离。监听地址若按文档改为局域网地址，会扩大可访问范围。
- 应使用前端资源白名单，并将服务端数据移出静态可访问根目录。

### 2. P1：文件导入到不了预检步骤

- 位置：`app.js:140` 起的导入 change 处理；`src/app/views/settings.js` 的 `#import` 绑定。
- 设置页存在两个 `input#import`（侧栏和正文），`querySelector` 只绑定第一个。全局事件异步转交文件时，又先清空原输入。
- 实测：在设置页“导入备份（先预检）”选择合法的临时 v3 JSON，没有出现预检；控制台在 `app.js:151` 报 `DataTransferItemList.add: parameter 1 is not of type 'File'`。
- 应在异步操作前保存 File 引用，唯一化控件 ID，并收敛为一条导入流程。

### 3. P1：Agent 恢复后错误终止，无法收尾

- 位置：`src/app/views/lab-agent.js:181`、`:196`，对照 `src/labs/agent.js` 的 `finish()`。
- 浏览器复现：默认写入超时→刷新→点击“按策略恢复”。核验返回 confirmed；写入次数 1、预约记录 1，但页面显示“任务终止：目标未达成”，历史记为失败。
- `recoverStep` 将 `run.done` 提前设为 true，却没有调用 `finish` 设置最终 passed；`renderRun` 又因 done 禁用收尾按钮。
- 应在核验之后完成目标检查，再生成唯一终态和记录。当前纯引擎测试未覆盖这一视图编排路径。

### 4. P1：同步的前端合并和后端并发保护均有缺陷

- 前端位置：`src/app/views/settings.js:145`。合并后写的是 `s.state = merged`，并未替换应用的 notes/progress 等根字段。
- 隔离状态复现：合并后的 remote note 仅出现在嵌套 `state.notes` 中，`getState().notes` 没有该笔记；服务器与本机可能显示不同数据。
- 后端位置：`server/src/accounts.js:98`、`:122`。读 revision→检查→写文件没有按用户串行化。
- 实测：对同一用户并发发送两个 baseRevision=1 的不同更新，两次均返回 HTTP 200、revision=2；预期应有一个返回 409。存在更新被覆盖风险。
- 另：登录切换只改账户信息，不重置 revision；“用本机覆盖服务器”的 UI 声称会保存历史，但传入服务器当前 revision 后，后端仅在版本不一致的分支备份，通常不会生成所声称的历史副本。

### 5. P1：导入备份的保存顺序可能导致不可恢复覆盖

- 位置：`src/app/state.js:180`，尤其 `:189`、`:195`。
- 代码先 persist 新数据，再尝试保存旧数据备份，并吞掉备份失败。
- 隔离存储复现：只让 `ai-learning-import-backup` 写入抛 quota 错误；导入仍返回成功，旧笔记消失，备份不存在。
- 界面还宣称有服务端/本机双备份及下载备份，本条实际流程没有落实这些承诺。
- 应先确认旧数据备份可靠保存，再覆盖；备份失败必须中止。

### 6. P2：四个视图引用不存在的刷新模块

- 位置：settings.js:237、tutor.js:134、library.js:308、lab-agent.js:257，均在 `src/app/views/`。
- `import('../app.js')` 解析成不存在的 `src/app/app.js`，真实入口在仓库根目录。
- 浏览器实测：添加视频链接后不显示新链接，控制台报 `Failed to fetch dynamically imported module .../src/app/app.js`。
- 影响设置操作后刷新、助教切换上下文、视频/笔记关联或恢复后的刷新、丢弃 Agent 检查点等交互；部分流程另有全局通知重绘，可能掩盖错误，但错误仍存在。

### 7. P2：RAG 控件与真实行为不一致

- 位置：`src/app/views/lab-rag.js:150` 起、`server/index.js:82`、`server/src/rag.js:70`。
- 浏览器选择“仅词项基线”并勾选“调用模型生成回答”：分支提前 return，只展示检索结果，生成和截断都被跳过。gold-evidence 的词项分支也把 generation 固定为 null，不能完成宣称的“给正确证据后比较生成”。
- 实际 API 请求 chunkSize=80、overlap=0，响应 overlap 变成 40；原因是 `Number(overlap) || 40` 把合法的 0 当作缺省值。
- 为该请求生成的 `index-builtin-80-40/meta.json` 实际写着 chunkSize=200、overlap=40。Node 构建索引时没有向 Python 传递分块参数，目录名并不代表真实索引配置。
- 生成评价仅检查引用 ID 是否在上下文，`grounded` 主要依据是否有引用格式或拒答词；不能据此认定答案事实得到证据支持。

### 8. P2：训练失败却显示“训练完成”

- 位置：`src/app/views/lab-embodied.js:287` 起的 launchTask/collect/train/evaluate。
- 实测在没有采集数据的隔离后端点击训练：任务 failed，日志明确 FileNotFoundError；输出卡仍为绿色反馈、“BC 训练完成（kind=own-training）”，历史标题为“BC 策略训练完成”。
- 回调不检查任务终态即展示成功内容；评测也未在失败后中止。
- 应只有 succeeded 才展示结果，失败时给具体恢复动作，训练前检查依赖。

### 9. P2：能力评价仍将“提交过”当成能力证据

- 位置：`src/app/views/course.js:175` 起的 bindQuiz；`src/app/record.js`；`src/app/state.js:238`。
- 实测提交“不了解，随便填写”性质的无效回答后，解释能力立即增加为 1 门；评分仍为 rubricSelf=pending，没有质量判断。
- 原因：任意非空回答都会调用 `setCapability(..., true)`。提交时全局重绘还会使填写内容和新结果显示脱节。
- 运行侧主要写 diagnosed/verified；地图和课程徽章主要读取 exercisePassed/experimentPassed/reviewed，缺少完整连接，首页 totalEvidence 又读取后一组字段。
- 应明确区分已提交、自评、程序通过、AI 建议和人工复核，统一证据和徽章的数据流。

### 10. P1：长期记录仍会静默丢失

- 位置：`src/app/state.js:64`、`src/core/schema.js:212`、`:241`。
- 实测写入 602 条运行，仅保留 100 活跃+500 归档=600 条，最早两条已丢弃；设置页却写“自动归档，不丢弃”。
- quizAttempts 在 normalize 中还截为最后 1000 条，与“作答保留全部”的文案不符；大运行集合在 normalize 中也有截断。
- 应在达到容量时明确提示/要求导出，或采用真正持久的分页归档，不能继续承诺永久保留。

## 其他实现与教学缺口

### 11. P2：任务执行没有落实独立产物目录和参数边界

- 位置：`server/src/tasks.js:90`、`:139`、`:144`；`server/index.js` 的任务路由。
- 源码确认：任务统一在 `DATA_DIR/artifacts` 工作；脚本没有利用 AI_LEARNING_TASK_DIR。两个采集或训练任务会写相同的固定文件，后续运行可覆盖前次证据。
- 产物清单却扫描 tasks/<id>，因此真实文件通常不出现在任务 artifacts 中。
- 白名单仅约束脚本名，未实际使用白名单中 args 规则；输出路径、输入模型路径、轮数等未做服务端范围限制。任务创建/读取/取消也没有按账户授权。
- 这不符合 ADR 所称的“每任务独立临时目录、权限、完整产物清单”。本项依据代码检查，没有对原用户文件执行破坏性探测。

### 12. P2：课程示例尚未逐段完成可运行验收

- 21 个标记为 Python 的代码块中，12 个实际包含终端命令，按 Python 源码解析会报 SyntaxError；这些块应标为 shell，并明确 Windows PowerShell 的续行规则（当前多处用 Bash 的反斜杠续行）。
- 具身 policy 第 3 步给 `--model artifacts/embodied/bc-model`，评测器实际要求权重文件 `.../policy.pt`，照抄会失败。
- foundation 第 2 步的预期输出断言“未提供事实就不会生成日期”，小模型不具备这项行为保证；应让学生观察幻觉或拒答的实际差异。
- 内容自动测试主要检查字段存在，不等于示例可执行或教学正确。

### 13. P2：部分故障演示缺少实际可观察效果

- 位置：`experiments/embodied/sim.py`。
- 目标固定不动，occlusion 只是反复取同一目标。实跑 none 与 occlusion 均 1 步成功、误差 0.0099，观测完全相同，无法表现页面解释的“遮挡锯齿”。
- Python 的 Rand 与 JS 标注的 mulberry32 也存在代码实现差异，跨端完全一致的主张需要逐帧数值测试。
- 应采用移动目标/真实缺失观测和有意义的恢复策略，并使说明对应实际轨迹。

### 14. 清单勾选超出了实际完成范围

- “完整小型论文复现实例”对应的 REPRO_EXAMPLE.md 自己声明只是模板，数值为示例，没有已执行的 ROME 复现包和实测产物。
- “接入开源仿真任务”被自研二维仿真替代；可作为教学选择，但不能算该原始要求已经满足。
- 自选语料仅走浏览器词项轨道，未形成自选资料的向量检索→生成完整流水线。
- 两个项目提供分阶段任务和实验入口，但项目特定的完整代码、数据版本、产物关联与独立验收仍需补齐；目前导出还会截断每条 evidence 至 4000 字符。
- 公网部署、真实第二台设备、外部全部 Notebook、完整公式排版仍是昨日文档列出的未执行项，本次没有改变其状态。

## 修复顺序建议

1. 先保护数据：静态目录隔离、可靠导入备份、同步并发及本机合并、长期记录容量。
2. 修通核心交互：文件导入、动态模块路径、Agent 终态、训练失败反馈。
3. 校正实验与教学：RAG 参数/生成/评价、能力状态、每任务产物、课程命令和故障演示。
4. 按真实完成度重写验收清单，再覆盖浏览器完整流程及失败路径。自动测试通过不能代替上述验收。

本次没有重验远程模型质量、全部外链内容、全新系统安装、所有辅助技术或真实第二台设备。以上已复现的缺陷不依赖这些外部条件。
