## 1. 用户目标与工作方式

用户希望用浏览器直接打开一个持续更新的学习平台，系统学习大模型、具身智能与科研实践，并能结合测绘遥感背景完成项目。平台应帮助学习者理解原理、运行实验、诊断失败、验证结论并积累成果。

- 以已经整合的 3.0/3.1 工作台为基准继续演进，保留有效课程、实验、资料、数据和方案；允许重构框架、架构、目录与页面。`main` 是发布分支，不是必须原样保留的产品实现。
- 维持一个正式学习入口、一套内容与数据模型。旧 Sites 地址只负责迁移提示和原域名备份导出，不再发展成另一套平台。
- 用户已授权修复、内容补充、GitHub 同步和公开发布。普通实现、回归、分支、PR 和既定项目的发布无需逐步询问；先完成可核对的结果。
- 接手时先检查当前适用指令、工作区改动、可用连接器、已有托管与环境配置。缺少密钥、托管条件或预算时集中说明，继续不依赖它们的工作；既有 GitHub Pages 发布授权不代表允许新购服务或接受新增付费订阅。
- 所有状态区分“实现存在”“本地实测”“线上实测”“尚待验证”。规则演示、历史结果回放、真实计算、模型调用、自己训练分别标注。
- 不把自报完成、提交答案、引用格式合法、脚本语法通过当作能力通过、事实正确或实验成功。
- 除非任务确实需要，不更换视觉风格；目前绿色学习工作台是用户确认要延续的版本。新增能力优先接入现有学习流程。

## 3. 优先级与依赖顺序

P0 指在线计算服务上线前必须完成的工作；不表示当前静态站点整体不可用。P1 是近期可靠性和学习流程改进；P2 是内容与研究能力深化。

| 阶段 | 任务 | 完成后应达到的结果 |
| --- | --- | --- |
| 第一阶段 | H01–H04 | 浏览器可连接受控在线计算、模型与同步，发布有校验和回滚依据 |
| 第二阶段 | H05–H09 | 学习数据和项目证据可追踪，保存状态可信，核心流程有端到端覆盖 |
| 第三阶段 | H10–H14 | 文档检索、项目、论文复现与开源仿真有可运行产物 |
| 第四阶段 | H15–H18 | 长期使用、阅读、评价与内容维护更完整 |

可以先做不依赖托管的 H05–H09；不要因等待云端条件暂停全部工作。每个阶段形成可使用版本，不把所有任务塞进一个无法审阅的大 PR。版本号按实际兼容性与交付范围决定，不预先承诺上线日期。
